# Atlas should leave one trail

Rui and I reviewed the proposed Atlas weekly brief and the way it would move decisions from calls into the team's workspace.

## Rui's objection

Rui objected to shipping the brief as a separate destination. His concern was not whether the generated brief would be accurate on day one. Even a correct weekly brief starts aging as soon as the project moves. People forward it, annotate it, and keep treating it as authoritative while the project note changes underneath it. The team ends up with competing answers and has to guess which one governs.

He argued that the durable artifact must live with the work: write a source meeting note into the existing workspace, connect it to the Atlas project page, and keep the evidence reachable. Any digest should remain a view over those source notes, never a replacement for them.

## Boundary we left open

We agreed not to auto-edit the canonical project page until a person can inspect the proposed change. The unresolved question is whether a backlink from the meeting note is enough for the first pilot, or whether Atlas needs a reviewed project-page roll-up.
