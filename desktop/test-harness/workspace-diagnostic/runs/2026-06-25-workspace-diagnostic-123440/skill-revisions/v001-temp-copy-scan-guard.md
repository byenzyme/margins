# v001 Temporary-Copy Scan Guard

Builds on: `skill-revisions/v000-baseline.md`.

## Failure Pattern

The `partial-enzyme-or-margins` fixture already contains tool-state directories.
Running `enzyme scan --vault <fixture-workspace>` without `--write-config` still
created runtime residue at:

```text
test-cases/partial-enzyme-or-margins/workspace/.enzyme/enzyme.log
```

That file was generated by the diagnostic substrate, not by the fixture. It has
been removed. The failure shows that "do not pass `--write-config`" is not a
complete read-only guarantee when `.enzyme/` or `.margins/` already exists.

## Changed Instruction Area

This revision keeps the v000 diagnostic contract and tightens only the Enzyme
scan boundary:

1. Before running Enzyme, inspect the fixture root for `.enzyme/` and `.margins/`.
2. If either directory exists, scan a temporary copy of the workspace instead of
   the fixture path.
3. If scanning the fixture path is unavoidable, record pre/post mutation guards
   around hidden tool-state directories and note files.
4. Treat cache building, import materialization, and structural repair as three
   separate optional actions in the diagnostic. Do not merge them into "setup" or
   imply any one is required for first capture.

## Required Evaluator Procedure

For each case:

- Record the active revision as `skill-revisions/v001-temp-copy-scan-guard.md`.
- Snapshot the fixture before any Enzyme command. Include at least `.enzyme/`,
  `.margins/`, Markdown files, JSON/TOML config, and workspace root mtimes when
  practical.
- If `.enzyme/` or `.margins/` exists, create a temporary copy outside
  `test-cases/`, run `enzyme scan --vault <temp-copy>`, and store the scan
  output in the run artifact directory.
- Record the exact temporary path and the copy command or method in
  `evaluator-trace.md`.
- After scanning, compare the original fixture snapshot against the post-scan
  state. The original fixture must be unchanged.
- If any residue is detected, record the path, remove only residue proven to
  have been generated by the scan, and mark the case as requiring verifier
  rerun through the temporary-copy path.

Preferred command shape for a guarded fixture:

```bash
tmpdir="$(mktemp -d)"
cp -R "<fixture-workspace>" "$tmpdir/workspace"
enzyme scan --vault "$tmpdir/workspace"
```

The evaluator may use a more robust copy command when preserving symlinks,
permissions, or platform metadata matters. The invariant is that Enzyme reads a
throwaway workspace and all diagnostic artifacts are written under the run root,
not inside `test-cases/`.

## Diagnostic Framing Update

Keep first-capture language separate from later setup actions:

- **Private search cache:** reads the workspace and writes cache/runtime files,
  usually under `.enzyme/`; it should not rewrite notes.
- **Import history:** copies or converts outside material into a chosen import
  destination after preview; it preserves originals.
- **Retrieval repair:** small approved changes that improve future lookup, such
  as adding missing dates or entity handles only where existing conventions make
  that safe.

Do not describe these as one combined initialization step. A user should be able
to accept the note destination, start recording, and defer all three actions.

## Why This Generalizes

Many real workspaces are partially configured: users may have an old `.enzyme/`
cache, an `.margins/` app directory, a failed setup attempt, or a copied project
folder with stale runtime state. A scan that is read-only for fresh folders can
still append logs or touch state in these partial-cache cases. Temporary-copy
scanning preserves fixture integrity and mirrors the product boundary Margins
needs: reading workspace shape is separate from writing a private cache.

The separation of cache, import, and repair also generalizes across workspace
classes. Code repos, Drive exports, transcript dumps, daily-note vaults, and
messy Obsidian folders can all start capture before any cache build, historical
import, or structural cleanup.

## Cases Expected To Improve

- `partial-enzyme-or-margins`: avoids `.enzyme/enzyme.log` residue and forces the
  diagnostic to explain existing cache/app state without mutating it.
- `mixed-messy-power-vault`: keeps optional retrieval repairs distinct from
  capture readiness.
- `google-drive-export`: keeps import/materialization separate from private
  cache setup and first capture.
- `zoom-transcript-dump`: prevents transcript import/cleanup language from
  sounding like a prerequisite to record the next meeting.
- Any future fixture with stale `.enzyme/`, `.margins/`, or failed initialization
  state.

## Cases At Risk Of Regression

- `fresh-empty`: the added guard should not make an empty workspace sound
  complicated. The diagnostic should still say capture can start now.
- `append-only-dated-log`: repair/cache language must not undermine the clear
  existing convention.
- `codebase-plans-folder`: cache/import/repair separation should not obscure the
  simple destination recommendation, usually a docs meeting-notes folder.

## Old vs New Example Language

Old:

> I ran a read-only Enzyme scan without `--write-config`, so the fixture was not
> changed.

New:

> This workspace already has tool state, so I scanned a temporary copy and
> compared the original before and after. The original files were unchanged.

Old:

> Initialize Enzyme later if you want better retrieval.

New:

> Building the private search cache is a separate later action. It writes cache
> files, not note edits. Importing old material and repairing note structure are
> separate choices, and neither blocks the next capture.
